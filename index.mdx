tracehill gives you AI functions that learn from your feedback. Describe what goes in and what should come out, and you get typed values back, with no prompt to write, no model to choose and no parser to maintain. Then tell tracehill how each call went, and it uses that feedback in real time to make the next call better.

```python
import tracehill as th

client = th.Client()  # reads TRACEHILL_URL
result = client.predict(
    state={"ticket": "My card was charged twice"},
    outputs={
        "category": th.Choice(["billing", "bug", "other"]),
        "urgent": th.Bool(instructions="Needs a reply today?"),
    },
    instructions="Triage support tickets.",
)
result["category"]  # "billing"
result["urgent"]    # True
```

When you know how the call worked out, tell tracehill. Every later call of the same function benefits:

```python
result.feedback(feedback="Right team, but it wasn't urgent", metric=0.5)
```

## How it works

<Steps>
  <Step title="You describe a task">
    A request has a `state` (the input), named `outputs` (each with a type) and optional `instructions`.
  </Step>
  <Step title="tracehill runs it">
    tracehill writes the prompt, calls the model and converts each answer to the type you asked for. You never pick or configure a model.
  </Step>
  <Step title="You get typed outputs">
    A `bool` comes back as `true`/`false`, and a `choice` is always one of your labels. The prediction is stored with an `id`.
  </Step>
  <Step title="You add feedback whenever you know more">
    Attach a natural-language note, a metric, or both, as many times as you like.
  </Step>
  <Step title="tracehill learns">
    Feedback is grouped by task, and tracehill uses it in real time to improve that task's future calls, refining its instructions and learning from its best runs. You don't retrain or redeploy anything.
  </Step>
</Steps>
